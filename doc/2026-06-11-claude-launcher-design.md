- **日期**: 2026-06-11
- **状态**: 设计已锁版，待实现
- **交付目标**: 本文档自包含，可直接交给 Claude Code 开始实现，无需回看设计对话。

## 1. 背景与目标

### 1.1 背景
国内学生需要稳定、低封号风险地使用 Claude。链路方案为：

```
学生电脑 → ClashMi(本地代理, TUN模式) → 机场美国节点(中转跳) → 美国独立家宽静态IP(纯净出口) → Claude
```

独立家宽静态 IP 来自 NovProxy 一类「长效静态 ISP / 住宅代理」服务商，凭据形式为 **IP + 端口 + 用户名 + 密码**（账密模式）。用一个固定的纯净美国家宽 IP 作为最终出口，是降低 Claude 封号风险的核心。

### 1.2 软件定位（务必牢记）
本软件是 **配置生成器 + 链路体检仪表盘 + Claude 起停开关**。它**不接管代理、不开关 TUN、不切换节点**——这些由学生在 ClashMi(zashboard) 里手动完成。软件信任 ClashMi 已就位，只负责「生成配置、验证链路、展示状态、起停 Claude」。

### 1.3 目标（第一期，全部交付）
- 把老师的 Clash 模板 yaml 注入合成成学生可用的成品 yaml。
- 启动 Claude 前实测出口 IP，确保走在纯净链路上（安全兜底）。
- 一键起 / 一键安全关 Claude（Claude Code / 桌面 App / 浏览器三选其一）。
- 体检「独立 IP 出口链路」的延迟与稳定性（zashboard 的盲区）。
- 跳转 ping0.cc 让学生肉眼确认 IP 纯净度 / 类型。

### 1.4 非目标（明确排除）
- ❌ **不做 TikTok 电商 / 其它 LLM 的独立链路**。本软件只服务 Claude。架构上预留「多节点注入」能力，但第一期一行 TikTok 代码都不写。
- ❌ **不接管代理、不自动开 TUN、不自动切节点**。
- ❌ **不调用第三方 IP 信誉 API 算纯净度**（改为跳转 ping0.cc）。
- ❌ **不测机场节点的延迟/丢包**（学生直接看 zashboard）。
- ❌ **不号称抹除记录/防追踪**。「安全关闭」仅指干净结束 Claude 进程。

### 1.5 平台
- **Windows**（第一期唯一目标平台）。

## 2. 整体架构

单个 Tauri `.exe`，双击运行，内部分两层：

- **前端（界面层，Web 技术）**：学生看到与操作的全部 UI。两个主页面：
  1. 「配置生成」表单页（首次用 / 换 IP 时用）
  2. 「状态盘」主页（日常用）
- **后端（Rust 核心层）**：所有系统级操作——读写文件、调 Clash API、测延迟、起/杀进程、跳浏览器、yaml 注入。前端只发指令、收结果，不直接碰系统。

### 2.1 两个核心数据来源
1. **老师的模板 yaml**（`MAXs_20260609_01.yaml` 为基底，需加注入锚点标记，见 §6.1）——配置生成器的底子。
2. **Clash REST API**（`http://127.0.0.1:9090`，secret `123456`，端口/secret 从生成的 yaml 实际读取，不写死）——状态盘体检数据来源。

### 2.2 两条主线流程
- **首次配置流（学生跑一次，换 IP 时重跑）**：见 §5.1
- **日常使用流（每天跑）**：见 §5.2

## 3. 技术栈

- **框架**: Tauri (Rust 后端 + Web 前端)。
- **前端**: 任意轻量方案（建议原生 HTML/CSS/TS 或一个轻框架，避免把 exe 撑大）。
- **后端**: Rust。HTTP 请求用 `reqwest`，进程管理用 `std::process` / `sysinfo`，yaml 处理见 §6.1（**文本注入，不做完整解析重写**）。
- **打包**: 产出单 `.exe`（约 10MB 级，免安装）。
- **构建**: 提供 GitHub Actions，推代码云端自动产出 Windows exe（开发者本地可不装完整工具链）。

> ⚠️ 交付现实：设计/源码可交付；最终 build 出可双击的 exe 需在 Windows 本地或 CI 完成；分发 exe 涉及代码签名（否则 Windows SmartScreen / 国内杀软可能拦截），第一期可先不签名，提示学生放行。

## 4. 本地配置（软件状态存储）

软件在本地维护一个 `config.json`（路径建议 `%APPDATA%/claude-launcher/config.json`），由配置生成器写入、状态盘读取：

```jsonc
{
  "version": 1,
  "exitBasisIP": "207.97.137.112",   // 验证基准：学生填的 NovProxy server 值（若为域名需解析为 IP，见 §7.3）
  "proxyEndpoint": "http://127.0.0.1:7893", // 从生成的 yaml 读 mixed-port 拼成
  "clashApi": { "url": "http://127.0.0.1:9090", "secret": "123456" }, // 从 yaml 读 external-controller / secret
  "generatedYamlPath": "C:/Users/xxx/claude-clash.yaml", // 上次另存为的路径
  "claudeCodeCommand": "claude",     // CLI 启动命令（可让老师/学生覆盖）
  "lastUpdated": "2026-06-11T00:00:00Z"
}
```

**关键**：`exitBasisIP` 等抽象值**全部来自学生在配置生成器里的输入**，软件里无任何写死的 IP。换 IP / 换服务商时重跑配置生成器即自动更新（见 §5.4）。

## 5. 关键流程

### 5.1 首次配置流（模块1）
1. 学生打开「配置生成」页。
2. 软件加载内置的**带锚点标记的模板 yaml**（老师的 yaml + 注入标记）。
3. 学生填写表单（§6.1）：机场订阅链接、NovProxy(server/port/账号/密码)、协议(socks5/http 下拉)。
4. 后端执行**文本锚点注入**（§6.1）生成成品 yaml。
5. 后端**校验**成品 yaml（§6.1 校验清单）。
6. 全绿 → 弹「另存为」对话框存成 `.yaml`；同时把 `exitBasisIP`、端口、API 信息写入 `config.json`。
7. 学生**手动**把生成的 `.yaml` 拖进 ClashMi。

### 5.2 日常使用流（模块2 + 4 + 5 + 6）
前提：学生已手动开好 ClashMi + TUN + 在 zashboard 选好美国节点。
1. 学生打开状态盘，点「一键代理」。
2. 后端按序体检（§6.2）：查 ClashMi → 多源查出口 IP 与基准精确比对 →（顺带）独立 IP 链路延迟/稳定性。
3. 全绿亮绿灯；任一步失败 → 红灯 + 具体提示，**不放行**。
4. 学生点三个启动按钮之一：「启动 Claude Code」/「启动桌面 App」/「打开网页」。
5. （可选）点「在浏览器查看 IP 纯净度」→ 跳 ping0.cc。
6. （可选）点「测试独立 IP」手动复测链路。

### 5.3 安全关闭流（模块3）
1. 学生点「一键安全关闭」。
2. 弹窗：「⚠️ 确认前请检查：claude.ai 网页是否已关闭？未关闭可能仍在联网。」 + 勾选框「☐ 我已确认 claude.ai 网页已关闭」 + 两个按钮「确认」(需勾选才可点) /「再等等」。
3. 点「确认」→ 强杀 Claude Code 进程 + Claude 桌面 App 进程；**不碰浏览器、不碰 ClashMi/TUN**。
4. 状态盘回到「未启动」初始态。

### 5.4 换 IP / 换服务商流
NovProxy 到期/挂了/换别家时：学生买到新凭据 → 回「配置生成」页重填四个值（+协议）→ 重新生成 yaml → 重新拖进 ClashMi。`config.json` 的基准自动更新。**软件零改动**。
- 前提：新服务商也是「IP+端口+账密」的 SOCKS5/HTTP 代理，且是**美国住宅/家宽/ISP** 属性。
- 若新家给的是 `ss://`/`vmess://` 链接或自建 VPS（非账密代理），则需改注入逻辑——属代码改动，不在「重填即可」范围内。

## 6. 模块详细设计

### 6.1 模块1：配置生成器（核心，技术含量最高）

**职责**：模板 yaml + 学生输入 → 文本注入 → 成品 yaml → 校验 → 另存为 + 写 `config.json`。

**学生填写项**（仅此几项）：
| 字段 | 说明 | 示例 |
|---|---|---|
| 机场订阅链接 | 覆盖模板 `proxy-providers.Nice.url` | `http://.../s/xxxx` |
| 独立IP server | NovProxy 的 IP 或域名 | `207.97.137.112` |
| 独立IP port | 端口 | `443` |
| 用户名 | 账密 | `xxx` |
| 密码 | 账密 | `xxx` |
| 协议 | 下拉 socks5 / http | `socks5` |

**注入方式：文本锚点注入（不解析重写）**
必须保住老师 yaml 里的全部注释（`# 快猫`、`# 火烧` 等）与 YAML 锚点（`&default` / `*default`）。做法是在模板里预埋注释标记，后端按标记定位做文本插入/替换。**禁止用 yaml 库 load 成对象再 dump**（会丢注释和锚点）。

**模板需新增的锚点标记**（实现时在老师 yaml 对应位置加这些注释）：

1. **节点注入点** —— 在 `proxies:` 段，`- {name: 拒绝, type: reject}` 之后加一行标记：
   ```yaml
   proxies:
     - {name: 直连, type: direct}
     - {name: 拒绝, type: reject}
     # <<INJECT_PROXY_NODE>>
   ```
2. **机场订阅 URL** —— 把 `proxy-providers.Nice.url` 的值替换为占位标记，或在其上方加标记后替换该行：
   ```yaml
     Nice:
       url: "<<AIRPORT_SUBSCRIPTION_URL>>"
   ```
3. **Claude 策略组** —— 把 `- {name: Claude, <<: *default}` 替换为显式定义（让 Claude 默认指向独立IP节点）：
   ```yaml
   # <<CLAUDE_GROUP>>
   ```
   注入后替换为：
   ```yaml
     - {name: Claude, type: select, proxies: [美国独立IP, 直连, 所有-手动, 所有-自动, 香港-自动, 台湾-自动, 日本-自动, 新加坡-自动, 韩国-自动, 美国-自动, 其他-自动, 拒绝]}
   ```
   （`美国独立IP` 放第一位 → 配合 `profile.store-selected: true`，新配置默认选中它。）
4. **验证回显域名路由规则**（技术必需，见下方说明） —— 在 `rules:` 段 `MATCH,其他` **之前**插入标记：
   ```yaml
   rules:
     # ...原有规则...
     # <<INJECT_VERIFY_RULES>>
     - MATCH,其他
   ```

**后端注入的具体内容**：

- 在 `<<INJECT_PROXY_NODE>>` 处插入独立 IP 节点（协议按下拉为 `socks5` 或 `http`）：
  ```yaml
    - {name: 美国独立IP, type: <协议>, server: <server>, port: <port>, username: <用户名>, password: <密码>, dialer-proxy: 美国-自动}
  ```
  `dialer-proxy: 美国-自动` 是链路灵魂：去往独立 IP 的流量先穿过「美国-自动」组（机场美国节点），实现 `机场美国节点 → 独立IP` 的链式中转。**挂的是组名「美国-自动」而非具体节点名**，所以学生在 zashboard 里换美国组内的节点不会断链。

- 在 `<<AIRPORT_SUBSCRIPTION_URL>>` 处填入学生的机场订阅链接。

- 在 `<<CLAUDE_GROUP>>` 处替换为上面的显式 Claude 组定义。

- 在 `<<INJECT_VERIFY_RULES>>` 处为每个验证回显域名插入一条规则，**强制它们走 Claude 组**（这样模块2的 IP 验证请求与 Claude 实际走向完全一致——若 Claude 组被误选成别的节点或链路没通，回显 IP 就不等于基准 IP，从而红灯拦截）：
  ```yaml
    - DOMAIN,api.ipify.org,Claude
    - DOMAIN,ifconfig.me,Claude
    - DOMAIN,ip.sb,Claude
    - DOMAIN,ipinfo.io,Claude
  ```

**链路验证（注入后立即可见的回报）**：以上注入让「验证出口 IP」这步可靠——验证请求经由与 Claude 完全相同的路径出去，任何错配都会被发现。

**校验清单（另存为前必须全绿）**：
1. 必填项非空；server/port 格式合法；端口数值范围合法。
2. 注入后 yaml 语法可被解析（仅作语法体检，不回写——用临时 parse 验证结构没被注入破坏）。
3. 4 个锚点标记都被成功替换（无残留 `<<...>>`）。
4. （可选，能做更好）机场订阅链接 HTTP 可达性探测。
5. ⚠️ **「这条链路真能连通 Claude」此处无法验证**（ClashMi 尚未加载新配置）——真正的连通验证在模块2「一键代理」里完成。

**输出**：另存为 `.yaml` + 写 `config.json`（`exitBasisIP` = server 值，`proxyEndpoint` = 从 yaml 读的 mixed-port）。

**多 IP 预留**：节点注入用「列表」而非「写死单节点」的代码结构，将来加第二个独立 IP 是「多填一项 + 多注入一个节点」，不必重构。第一期只接一个（Claude）。

### 6.2 模块2：一键代理（启动）

**职责**：体检放行 → 拉起 Claude。**不接管代理、不开 TUN、不切节点。**

**点「一键代理」后按序执行（全绿才放行启动）**：

1. **查 ClashMi 在不在** —— 请求 Clash API（`config.json` 里的 `clashApi`）。不通 → 红灯「请先打开 ClashMi」。
2. **验证出口 IP == 基准 IP（安全兜底核心）**：
   - **多源查出口 IP（容灾）**：通过本地代理端口（`-x <proxyEndpoint>`，即经 mixed-port `7893`）依次请求一组回显源：`api.ipify.org` → `ifconfig.me` → `ip.sb` → `ipinfo.io/ip`，谁先成功用谁；全挂才报错。
     - 这些域名已被模块1注入规则**强制走 Claude 组**，故回显的就是 Claude 实际出口 IP。
   - **与基准精确比对**：回显 IP 是否 `==` `config.json.exitBasisIP`。
     - 相等 ✅ → 链路 `机场美国节点 → 独立IP` 真的通了，放行。
     - 不等 ❌ → 红灯 + 智能提示：回显是国内 IP → 「你没选美国节点」；回显是其它 IP → 「链路未走通 / 节点选错 / NovProxy 可能未连通」。
   - **比对标准只能是基准 IP，不能放宽成「只要是美国 IP 就行」**——否则学生挂机场美国节点（未走 NovProxy）也会被误判绿灯，兜底失效。
3. **独立 IP 链路体检（模块4，启动时自动测一次）** —— 见 §6.4，测延迟 + 稳定性并显示。
4. **拉起 Claude（三按钮，学生点哪个起哪个）**：
   - **Claude Code (CLI)** → 后端起一个带环境变量的终端会话：
     ```powershell
     $env:HTTPS_PROXY="<proxyEndpoint>"
     $env:HTTP_PROXY="<proxyEndpoint>"
     $env:NO_PROXY="localhost,127.0.0.1,::1"
     <claudeCodeCommand>
     ```
     记下该进程 PID（供模块3精确关闭）。
   - **桌面 App** → 直接启动 Claude 桌面客户端进程（走系统 TUN，不需环境变量）。
   - **浏览器** → 打开 `https://claude.ai`（系统默认浏览器）。

**端口处理**：`proxyEndpoint` 的端口**从生成的 yaml 实际读取**（`mixed-port: 7893`），不写死。（注意：早期截图里的 `7898` 是另一套非 TUN 方案的端口，本设计不用。）

### 6.3 模块3：一键安全关闭

**职责**：干净熄火 Claude 一侧。**不碰浏览器、不碰 ClashMi/TUN。**

**流程**：
1. 点「一键安全关闭」→ 弹**二次确认**对话框：
   - 文案：「⚠️ 确认前请检查：claude.ai 网页是否已关闭？未关闭可能仍在联网。」
   - 勾选框：「☐ 我已确认 claude.ai 网页已关闭」（未勾选时「确认」按钮禁用）。
   - 按钮：「确认」（勾选后可点）/「再等等」（收起对话框，不执行）。
2. 点「确认」后：
   - **强杀 Claude Code 进程**：优先用模块2记下的 PID 精确结束（含子进程）。
   - **强杀 Claude 桌面 App 进程**：按进程名查找并强制结束。
   - 直接强制结束即可（学生是用完关闭，不涉及未保存数据，无需先优雅退出）。
3. 状态盘回到「未启动」初始态（绿灯熄灭，回到等待「一键代理」）。

**浏览器为何不杀**：操作系统层面无法只精准关掉「那一个 claude.ai 标签页」而不动其它标签；只能整关浏览器（会误伤其它标签）。故设计为「浏览器你自己关、进程交给软件杀」，用二次确认勾选框降低「假确认」手滑。

**安全语义对齐**：「安全关闭」= 干净结束 Claude 进程、不留游离进程；**不**改变出口 IP、**不**抹除记录。

### 6.4 模块4：独立 IP 链路体检（瘦身版）

**为何只测独立 IP**：机场节点的延迟/丢包学生看 zashboard 即可。但 NovProxy 是挂在美国节点后面的 `dialer-proxy`（链末出口），**zashboard 看不到「机场美国节点 → NovProxy → 外网」整条链路的健康**——这正是它的盲区，也是本模块唯一要测的对象。

**测两个指标**（均经由完整链路）：
1. **延迟**：通过本地代理端口请求一个轻量目标（建议复用验证回显域名，已强制走 Claude 组），测往返耗时。这是**整条链路的真实延迟**，比 zashboard「只到机场节点」更真实。
2. **稳定性（代替丢包率）**：连发 N 次（建议 10 次）小请求，统计成功率。
   - ⚠️ 严格 ICMP ping 对「账密代理」出口测不了（代理不转发 ICMP），故用「多次小请求成功率」代替，对本场景意义一致（链路稳不稳）。

**触发时机（已定）**：
- **启动时自动测一次**（模块2 第3步顺带）。
- **状态盘放「测试独立 IP」按钮**，可手动复测。

**展示**：状态盘显示如「独立 IP 出口：延迟 280ms ｜ 链路稳定性 10/10 ✅」。

### 6.5 模块5：IP 体检（纯净度 / 类型）

**实现**：状态盘放一个按钮「在浏览器查看 IP 纯净度」→ 打开 `https://ping0.cc`。纯净度百分比、IP 类型（家宽/机房/移动）全交给 ping0.cc 网页呈现。**零 API 成本、无需 key**。

**前提（已满足）**：学生走全局 TUN，选了美国节点后全局走独立 IP，故浏览器跳 ping0.cc 时它看到的就是 NovProxy 出口 IP，能正确反映纯净度。

### 6.6 模块6：状态盘（主面板）

把模块 2/3/4/5 串成一个面板：
- **配置生成入口**（跳模块1 表单页）。

## 7. 安全模型与关键技术点

### 7.1 安全兜底核心
不管学生在 zashboard 怎么选节点，**启动 Claude 前实测出口 IP 是否 == 基准 IP，不等则红灯拦截**。验证请求经由与 Claude 完全相同的路径（注入规则强制回显域名走 Claude 组），因此任何错配（选错节点、NovProxy 未连通、Claude 组被改）都会被发现。

### 7.2 提供商无关
软件只认抽象凭据（server/port/账/密/协议），无任何写死的 IP/品牌。换任意「美国静态住宅 + 账密代理」服务商，重跑配置生成器即可，软件零改动。

### 7.3 待实现者验证的开放技术点（实现/测试阶段确认）
1. **协议与 TLS**：NovProxy 端口为 443。若协议选 `http` 且对方是 **HTTPS 代理**，Clash 节点可能需要额外 `tls: true`。实现时需对 socks5 / http(+tls) 两种都测通；必要时把 `tls` 也做成生成器选项。
2. **基准 IP 为域名的情况**：若学生填的 server 是域名而非 IP 字面量，比对时需把回显 IP 与「域名解析出的 IP」比较（解析可能多个 IP / 轮换）。NovProxy 给的是 IP 字面量，属主路径；域名情况作为边界处理。
3. **`dialer-proxy` + TUN(gvisor) + `endpoint-independent-nat` 组合**：链式代理在该 TUN 栈下需实测确认稳定。
4. **Claude 桌面 App 进程名**：实现时确认 Windows 上 Claude 桌面客户端的真实进程名以便精确查杀。
5. **exe 签名 / 杀软误报**：第一期可不签名，但需给学生「如何放行 SmartScreen / 杀软白名单」的说明。

## 8. 错误处理总则
- 体检每一步失败都给**具体、可操作**的中文提示（指明是「ClashMi 没开」「没选美国节点」「链路没通」还是「NovProxy 未连通」），而非笼统报错。
- 多源查 IP 全部失败时，提示「无法检测出口 IP，请检查 ClashMi 与网络」，**不放行**。
- 注入校验失败时，明确指出是哪一项（缺字段 / 格式错 / 锚点未替换 / yaml 语法坏）。
- 一切「拦截」默认偏保守：**有疑问就不放行**，宁可让学生多检查一次，也不放他走没保护的链路。
